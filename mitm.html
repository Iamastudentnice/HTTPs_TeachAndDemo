        Technical details: IP vs MAC addresses, ARP requests, replies and tables
        
    
          
    IP address (192.168.1.1): a logical address used to route across networks. MAC address (00:11:22:33:44:01): the hardware address that actually delivers frames on the local network.
    
          
    ARP request: a broadcast asking "Who has 192.168.1.1?". ARP reply: "192.168.1.1 is at 00:11:…". Devices cache answers in their ARP table.
    
          
    ARP has no authentication, so a forged reply simply overwrites the table. ARP spoofing only works on the local network - and even then, HTTPS content stays encrypted.

    Learn more: passive and active attackers
    
      
      
      Passive attackers watch and copy traffic. Encryption defeats them.
      
      
      Active attackers change, inject or impersonate. Certificate checks and HSTS defeat them.
      
    
      
  
      
  
      
    Learn more: when HTTPS can still be intercepted
    
      
      
      HTTPS stops passive reading and silent modification. It does not make interception impossible:
      
      
      Certificate warnings ignored - if the user clicks through, the attacker's certificate is used and the attacker can decrypt (scenario C).
      
      
      Malicious root CA installed - a fake certificate then passes every check, with no warning (scenario C, "trusted rogue CA").
      
      
      First visit over HTTP - without HSTS, an attacker can keep the victim on HTTP (TLS stripping, scenario D). HSTS and HTTPS-Only Mode prevent this.
